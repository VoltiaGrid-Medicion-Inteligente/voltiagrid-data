# Development subset

US-03 (KAN-77), T-03.3 (KAN-87). Generated by `python dev_subset.py` from `informations_households.csv`.

## Why complete blocks

The half-hourly readings (F1) are split into 112 block files and Kaggle groups households into blocks by ACORN group and tariff. Taking the first 200 households in alphabetical order touches most of the blocks, so a developer would still read almost the whole 7.5 GB dataset.

The development subset is a small set of **complete blocks**. Loading it means reading only those files, and every household in them has its full history.

## How the blocks are chosen

1. Blocks are added one at a time. Each step takes the block that keeps the subset closest to the full dataset's shares of ACORN group (`Acorn_grouped`) and tariff (`stdorToU`), measured as the sum of absolute differences. Ties go to the block closest to 50 households, then the lowest block number.
2. It stops when the subset has at least 200 households and every ACORN group with at least 1% of the households and both tariffs (`Std` and `ToU`) are present. If a group or tariff is still missing, the next block must add it.

The result is deterministic: the same households file always gives the same blocks.

Groups below 1% are not forced into the subset: `ACORN-`, `ACORN-U`.

## How to use it

```bash
python profile_dataset.py --dev      # profile only the subset -> docs/data/profile-dev.md
```

In Spark code, read only the subset files:

```python
from dev_subset import load_dev_blocks, select_files

paths = select_files(all_block_paths, load_dev_blocks())
df = spark.read.csv([str(p) for p in paths], header=True, schema=F1_SCHEMA)
```

To change the rule, edit `dev_subset.py` and run `python dev_subset.py` again; commit the new `dev_subset.json` and this page together.
